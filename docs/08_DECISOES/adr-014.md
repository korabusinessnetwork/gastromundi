# ADR-014: Camada gratuita de segurança do agente, e o que ficou de fora por custo

**Status:** Aceito e implementado
**Data:** 2026-09-14
**Decisores:** Matheus (founder)
**Supersede:** N/A
**Supersedido por:** N/A

## Contexto

O `CLAUDE.md` e o `memory/restrictions.md` já dizem o que o **código** precisa ter:
segredo em variável de ambiente, nada de `select *` em tabela sensível, input validado,
RLS configurada. O que não existia era regra sobre o outro lado do problema: **o agente que
escreve esse código não tinha revisor nenhum além dele mesmo.**

Isso é um defeito de forma, não de esforço. Quem escreveu não é bom revisor do que
escreveu, e nada muda esse fato pelo lado da IA. O ciclo `/spec`, `/build`, `/review` já
melhora o caso, mas as três etapas rodam no mesmo contexto e com a mesma cegueira.

Havia também um buraco de supply chain aberto: skill e plugin de terceiro entravam no
projeto por `git clone` sem nenhuma conferência. Uma skill é texto que o agente executa
como instrução. Instalar skill de terceiro sem ler é rodar código de terceiro sem ler.

A restrição de custo da fase de bootstrap (`memory/restrictions.md`) limita a resposta:
só entra por padrão o que é gratuito e roda sem consumir token.

## Decisão

### 1. Três ferramentas gratuitas entram como camada padrão

| Ferramenta | Origem | Papel | Escopo |
|------------|--------|-------|--------|
| `security-guidance` 2.0.8 | Anthropic, oficial | Revisor que não escreveu: regex no edit, review do diff no fim do turno, review agêntico no commit | Usuário (`~/.claude`), por máquina |
| `skillspector` 2.11.2 | NVIDIA, Apache 2.0 | Portão antes de instalar skill ou plugin de terceiro | CLI do sistema, por máquina |
| `vibesec` (commit `0590993`) | BehiSecc, comunidade | Contexto de código seguro para web no agente | `.claude/skills/vibesec/`, versionado |

As duas primeiras são configuração de máquina e não entram no repositório. O `vibesec` é
markdown puro, sem código executável, então entra versionado: quem clonar o repo já recebe
a skill, sem passo manual e sem depender de o clone remoto continuar existindo.

### 2. Nenhuma skill de terceiro entra sem `skillspector scan` limpo

Vira restrição permanente, registrada em `memory/restrictions.md`. Só o modo estático, que
não precisa de chave de LLM. O estágio semântico consome token e é decisão do dono, caso a
caso.

### 3. O score do scanner não decide sozinho, o achado lido decide

Ficou claro na primeira aplicação: o próprio `security-guidance`, plugin oficial da
Anthropic, pontua 100 e recebe `DO_NOT_INSTALL` no scanner da NVIDIA, porque ele lê a chave
de API do ambiente e a envia num cabeçalho HTTP. É exatamente o que um cliente de API faz,
e é a razão de ele existir. O `vibesec` pontua 95 pelo mesmo tipo de engano: cita
`rm -rf /`, `/etc/passwd` e um homóglifo cirílico dentro de tabelas que **documentam
ataques**.

Então o portão é: rodar o scan, ler cada achado alto ou crítico, conferir o trecho citado,
e registrar a conclusão. Instalar sem olhar é o que fica proibido, não instalar com achado.

### 4. Fica deliberadamente de fora o que consome token por execução

| Ferramenta | Por que não agora | Quando reabrir |
|------------|-------------------|----------------|
| `claude-security` (Anthropic) | Gratuito de instalar, mas cada varredura gasta token de verdade | Auditoria profunda antes do primeiro cliente pagante |
| `strix` (usestrix) | Precisa de Docker e de chave própria de LLM, custo real por execução | Pentest do app rodando, antes do primeiro cliente pagante |
| plugins `trailofbits/skills` | Gratuitos, mas o catálogo é majoritariamente smart contract, C e Rust, fora da stack | Auditoria de PR grande, ou repo com agente rodando em GitHub Actions |
| `trailofbits/skills-curated` | Resolve por curadoria o mesmo problema que o SkillSpector resolve por scan, redundante agora | Se passarmos a instalar plugin de comunidade com frequência |

## Consequências

**Positivas**

- O diff passa a ser revisado por quem não o escreveu, em três pontos do turno.
- Supply chain de skill deixa de ser porta aberta, e a regra é verificável por comando.
- O agente ganha contexto de classes comuns de vulnerabilidade web sem custo por execução.
- Zero investimento financeiro, coerente com a fase de bootstrap.

**Negativas e limites**

- **A camada não valida isolamento RLS entre tenants, que é o maior risco desta stack.**
  Uma policy que deixa o tenant A ler o pedido do tenant B não tem nada sintaticamente
  errado, e passa batido pelas três. A checagem de isolamento continua manual e
  obrigatória, conforme ADR-008.
- Também não sabe regra de negócio: fechamento de caixa e cálculo fiscal continuam
  cobertos só pela nossa suíte.
- Duas das três são configuração por máquina, então cada ambiente novo precisa dos dois
  comandos de instalação. O `docs/11_SEGURANCA/README.md` guarda esses comandos.
- O `vibesec` é de comunidade e tem versão paga no README dele, que fica fora do padrão.
  A cópia versionada aqui está congelada no commit citado acima, então atualização é ato
  consciente, com scan novo antes.

## Pendências

- Definir o teste automatizado de isolamento entre tenants, que é o buraco que esta camada
  não tapa.
- Reavaliar `claude-security` e `strix` antes de abrir o sistema para o primeiro cliente
  pagante, com custo aproximado na mesa.
